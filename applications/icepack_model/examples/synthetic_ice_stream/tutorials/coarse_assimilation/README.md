# A coarse Icepack assimilation case

We use this small configuration to follow a complete Icepack–ICESEE cycle without an external mesh or spin-up dataset. It delegates to the existing `synthetic_ice_stream/run_da_icepack.py` and its physics/hooks. This is a configured application example, rather than another solver implementation or a new native registration.

The inherited geometry and physical model use a generated 5,000 by 1,200 m rectangle. We reduce the mesh to 6 by 4 quadrilateral elements with degree-one fields, four ensemble members, one year, and ten forecast steps (`dt=0.1` year). Observations occur at 0.5 and 1.0 year, including the final state. The ordered blocks are `h,u,v,smb`; on one spatial rank their 35 nodes give a 140-row state and an expected `(140,4,11)` ensemble history. The true/unassimilated reference, synthetic observations, and member forecasts are generated by the established example.

The child YAML disables the optional inference plugin and localization for this first exercise, explicitly selects the legacy forecast-anomaly factor, and reduces prior/forecast perturbations. SMB is jointly estimated and synthetically observed. These choices define an illustrative experiment; its coarse solution and uncertainty amplitudes are not calibrated physical recommendations. The inherited `k_start_override:40` is explicitly cleared so this ten-step case actually starts at cycle zero.

## Run the case

From a checkout named `ICESEE`, activate its verified Icepack/Firedrake environment and set both import roots as in the deployment guide. A worktree with a different basename needs the documented import shim; verify `ICESEE.__file__` before running. All paths below are relative to the repository root except the required fresh output path.

```bash
CASE=applications/icepack_model/examples/synthetic_ice_stream/tutorials/coarse_assimilation
CASE_ROOT="$(mktemp -d "${TMPDIR:-/tmp}/icesee-coarse.XXXXXX")"
python "$CASE/run.py" --mode 2 --output "$CASE_ROOT/mode2" --check
```

The check resolves YAML inheritance and reports the actual source driver and expected sizes. It imports no Firedrake/Icepack solver and writes no run directory. The wrapper refuses an existing output directory so a fresh application import cannot remove earlier results there.

Using the launcher functionally verified against the active interpreter:

```bash
mpiexec -n 2 python "$CASE/run.py" \
  --mode 2 --output "$CASE_ROOT/mode2"
```

Use a new directory with `--mode 1` for the ordinary partially parallel path. Use a single Python process with `--mode 0` for the serial path. The wrapper fixes one model rank per member; it is not a multi-rank spatial validation. Use two ranks and `--output "$CASE_ROOT/mode3"` with `--mode 3` for the registered synthetic-stream native whole-member path. Its one-spatial-rank fields, persistent local members and file-backed analysis have different output and restart capabilities from the spatial PIG binding.

Mode 2 uses the installed stack's parallel HDF5. Retain stdout, stderr, exit status, `performance.json`, parameter inheritance chain, source SHA/import path, and the complete output tree. Full mode-2 VDS history requires its backing shards. Check both analyses at state columns 5 and 10, finite member/mean values, expected shape, and mean/member consistency after all writers close. Agreement between Modes 1 and 2 requires the same realized inputs and float64 history; a plot alone is not the comparison gate.

## What this teaches about onboarding

The new files supply configuration, an entrypoint wrapper, and a result-view declaration. Reusing the established entrypoint preserves its cwd-dependent hook discovery and registered model family. A new physics model would instead need its own initialization, forecast/observation/consistency hooks, layout, and capability validation; this wrapper does not create those automatically. Extend this case by changing one setting in another child YAML, naming a new output directory, and explaining whether that change affects physics, uncertainty, analysis, or only execution.

## Recorded execution and verification

This case was executed on 10 November 2026 in all four modes: one Python rank for Mode 0 and two MPI ranks for Modes 1–3. Every run completed ten forecasts and two analyses, with observations at columns 5 and 10. All four packed histories have shape `(140,4,11)`, finite values and positive thickness. Generic stored means match the members. Modes 1 and 2 agree across the full history with maximum absolute difference `2.007709554163739e-10`, within `rtol=atol=1e-7`. We do not claim four-mode member parity, calibrated uncertainty or physical skill from this fixture.

From the repository root, after writers close:

```bash
python scripts/docs/verify_sample.py "$CASE_ROOT/mode2/icesee_ensemble_data.h5" \
  --members 4 --columns 11 --rows 140
python scripts/docs/verify_sample.py "$CASE_ROOT/mode3" \
  --native-analysis-series --members 4 --columns 11 --rows 140
```

Mode 3 retains `native_analysis_0000.h5` through `native_analysis_0010.h5`, each with a `(140,4)` `states` dataset, plus `_mode3_state_history` manifests/shards. This binding does not export the generic ensemble history or a stored `ensemble_mean` by default. Preserve both native outputs; a generic-history check is inappropriate for that layout.

The [recorded results](../../../../../../paper/production-report/experiments/icepack-coarse-results.json) include the exact configuration hash, versions, analysis events and block extrema. The first local attempt failed PETSc's compiler check because an inherited `mpicc` selected MPICH while PETSc used Open MPI. Selecting the matching compiler in the child process environment allowed the recorded runs; importing Firedrake alone had not established a coherent compile stack. No installed environment was changed. See the [sample-run route](../../../../../../docs/handbook/sample-runs.md) for the Lorenz and ISSM exercises.
